1.3 핵심 설계 근거 (Design Rationale)
  1. 단일 의사결정 진입점 (rule_engine.py) 및 운영 모드 3종 분리: 현장 조업 조건에 맞춰 SAFETY_FIRST(불량 유출 FN=0 최우선, 임계치 0.600), BALANCED_THROUGHPUT(정상 재검 최소화, 임계치 0.645), HUMAN_IN_THE_LOOP(경계 점수 0.58~0.65 구간 2차 육안 확인 권고 플래그(manual_review_recommended=true))를 지원합니다. decision == "PASS"일 때 히트맵을 SUPPRESSED_BELOW_THRESHOLD로 동기화하고 패턴 추정을 NORMAL_WITHIN_SPEC으로 일원화하여 판정과 시각화 간 불일치를 원천 차단합니다.
  2. Primary Seed(42) 조도 층화 분할 단일화 및 교집합 0% 보장: 기본 메모리 뱅크(190장)와 기본 검증셋(30장) 분할을 seed=42 조도 층화 분할(brightness_stratified) 하나로 통일하여 기본 임계치와 per_seed.seed_42 임계치가 100% 일치하며, 교집합은 0장(bank_validation_overlap: 0)입니다.
  3. 부품 기하학(Geometry) 분리 정책 및 기능 범위 한계 명시: 국소 표면 결함(스크래치, 찍힘, 균열, 변색) 탐지에 최적화되어 있으며, part_geometry="generic" 응답에는 structural_shape_check="NOT_PERFORMED" 및 global_deformation_coverage="LIMITED"가 명시됩니다. 원형 너트 데모 시에는 part_geometry="circular_jig"로 지정하여 전경 중심 기반 링 마스크(0.58 <= r <= 0.95)를 선택 적용합니다.
  4. API-Streamlit 상태 동기화 및 무결성 검증: 모든 검사 응답에 model_part_id, model_sha256, model_version, activated_at 메타데이터를 포함하며, 대시보드에서 실시간 대조 후 불일치 시 즉각 시각적 경고 배너를 띄웁니다.

2.1 [반론 1 반영] 기준 Python 환경 (Python 3.12 64-bit) 및 SHA256 검증

오프라인 패키지 폴더(wheels/)에 포함된 C 확장 바이너리(torch, torchvision, numpy, scipy, pillow, pydantic_core 등)는 Windows 64-bit + Python 3.12 (cp312-cp312-win_amd64) ABI를 기준으로 빌드되어 있습니다.

  • Python 3.12.x (64-bit): wheels/ 폴더를 통해 인터넷 없이 즉시 설치 및 실행 가능 (정상 진행)
  • Python 3.11 / 3.13: setup_and_run.bat가 경고를 출력한 뒤 진행을 시도하나, 오프라인 환경(--no-index)에서는 순수 Python 패키지만 설치되고 torch 등 핵심 C 확장 패키지 설치가 실패할 수 있음 (설치 또는 import torch 실패 시 명확한 오류 및 가이드 출력 후 중단)

Python 3.12 공식 설치 파일 및 무결성 검증

  • 릴리스 페이지: https://www.python.org/downloads/release/python-31210/
  • 설치 파일명: python-3.12.10-amd64.exe (Windows installer, 64-bit, 약 25.4 MB)

3) 조건부 조치: Windows DLL 로드 오류 (VC++ Redistributable)

Python 3.12 공식 설치본은 기본 vcruntime140.dll을 포함하지만, 포맷 직후의 일부 클린 Windows 환경에서 ImportError: DLL load failed while importing _C (WinError 126) 오류가 재현될 수 있습니다. 재현되지 않는 환경에 불필요한 설치 파일을 강제하지 않으며, 해당 오류가 실제로 발생한 경우에 한하여 아래 패키지를 설치합니다.

  • 대상 패키지: Microsoft Visual C++ 2015–2022 Redistributable (x64) (vc_redist.x64.exe, 약 13.9 MB)
  • 공식 안내 URL: https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist

5.1 현재 단일 활성 모델의 한계 및 LRUModelCache 확장 다이어그램 (Inline SVG)

현재 버전은 단일 라인·단일 활성 모델(_ACTIVE_ENGINE) 전제로 구현되어 해커톤 데모에서 CPU 평균 103.4ms 성능을 검증했습니다. 다품종 혼류 라인(M12 볼트, M16 너트, 베어링 등 동시 유입)으로 확장할 때 발생하는 전역 Lock 대기 및 RAM OOM을 해결하기 위해 요청 단위 part_id 지정 + Top-K 인메모리 LRUModelCache + 모델별 세분화 RLock 아키텍처를 설계했습니다.

5.2 `LRUModelCache` 레퍼런스 구현 및 관측성(Observability) SLA 
class LRUModelCache:
    """Top-K 부품 모델을 인메모리에 유지하며, 모델별 세밀한 RLock을 제공하는 스레드 안전 캐시"""
    def __init__(self, max_models: int = 5, models_dir: Path = Path("models")):
        self.max_models = max_models
        self.models_dir = models_dir
        self._cache: OrderedDict[str, PatchCoreEngine] = OrderedDict()
        self._locks: dict[str, threading.RLock] = {}
        self._global_lock = threading.RLock()

    def get_engine_and_lock(self, part_id: str) -> tuple[PatchCoreEngine, threading.RLock]:
        with self._global_lock:
            if part_id not in self._locks:
                self._locks[part_id] = threading.RLock()
            lock = self._locks[part_id]
            if part_id in self._cache:
                self._cache.move_to_end(part_id)
                return self._cache[part_id], lock
            if len(self._cache) >= self.max_models:
                self._cache.popitem(last=False)
            engine = PatchCoreEngine(model_path=self.models_dir / f"{part_id}.pt")
            self._cache[part_id] = engine
            return engine, lock
